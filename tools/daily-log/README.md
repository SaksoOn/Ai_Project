# 일일 업무기록 · 주간보고 자동화

Outlook에서 오늘 한 일을 긁어 **대기열**로 만들고, 업무가 아닌 것만 지우면 기록이 됩니다.
주간보고는 그 기록으로 자동 생성됩니다.

## 왜 "지우는" 방식인가

원래 방식은 자동으로 채우고 나머지는 기억해서 추가하는 것이었습니다. 그런데
**떠올리는 것보다 알아보는 게 훨씬 쉽고 빠릅니다.**

| | 추가하는 방식 | **지우는 방식** |
|---|---|---|
| 인지 부하 | "오늘 뭐 했지?"를 떠올려야 함 | 목록 보고 지우기만 |
| 누락 | 잊은 건 영영 안 들어감 | 다 올라와 있어 누락 없음 |

그리고 **쓸수록 지울 게 줄어듭니다.** 늘 지우던 상대는 다음부터 자동으로 빠집니다.

## 설치

```bash
pip install openpyxl pywin32
cp config.example.toml config.toml
```

`config.toml`에 **본인 메일 주소와 부서 주소만** 채우면 됩니다.
비밀번호는 필요 없습니다 — 이미 로그인된 Outlook을 그대로 씁니다.

## 막히면 먼저 이걸 돌리세요

```bash
python run.py doctor          # 환경 진단. 아무것도 쓰지 않습니다
python run.py doctor --verbose  # 대기열 미리보기까지
```

Python·패키지·설정·폴더 권한·Outlook 연결을 차례로 확인하고, **뭐가 왜 안 되는지**를
한 화면에 보여줍니다. 막히면 이 결과를 그대로 복사해 물어보시면 됩니다.

수집은 됐는데 대기열이 0건이면 대개 **config.toml의 메일 주소가 Outlook에 보이는 주소와
다른 경우**입니다. doctor가 그것도 짚어줍니다.

## 먼저 흉내내 보기 (Outlook 없이)

```bash
python run.py demo
```

가짜 하루로 대기열이 만들어집니다. 엑셀을 열어 몇 줄 지우고 저장한 뒤
`confirm` → `weekly`를 돌려보면 실제와 같은 흐름을 확인할 수 있습니다.
**진짜 메일을 건드리기 전에 이걸 먼저 해보세요.**

## 하루 흐름

```bash
python run.py collect     # 오늘 메일·일정 → 대기열 엑셀
#   → 엑셀 열어 업무 아닌 행 삭제, 저장
python run.py confirm     # 남긴 것 확정 + 지운 패턴 학습

python run.py weekly      # 금요일: 이번 주 기록 → Outlook 초안
```

`collect`는 하루 한 번, 퇴근 전이 좋습니다. 하루에 여러 번 돌려도 안전합니다
(같은 날을 다시 확정하면 덮어씁니다).

## 무엇이 대기열에 오르나

| 대상 | 기본값 |
|---|---|
| 내가 보낸 메일 | ✅ |
| 내가 To로 받은 메일 | ✅ |
| 부서 주소로 온 메일 | ✅ |
| 나만 참조(CC)된 메일 | ❌ 대개 업무가 아니라 꺼둠 |
| 일정 | ✅ |

각 행에 **왜 올라왔는지**가 적힙니다. "이게 왜 여기 있지?"를 바로 알아야 판단이 빨라집니다.

## 학습

지운 기록이 쌓이면 **늘 지우던 상대는 자동으로 뺍니다.** 뉴스레터, 시스템 자동알림 같은 것들이요.

보수적으로 잡혀 있습니다 — **5회 이상 봤고 그때마다 전부 지운 경우에만** 제외합니다.
한 번이라도 남긴 적이 있으면 계속 올립니다. 잘못 빼면 사용자가 그 사실조차 모르기 때문입니다.

자동으로 뺀 것은 `자동 제외됨` 시트에 그대로 보입니다. 잘못 뺀 게 있으면 되살릴 수 있습니다.

## 안 되는 것

- **Windows + Outlook 설치본에서만** 동작합니다. 웹(OWA)만 쓰면 Graph API 등록이 필요합니다.
- **카카오톡·ZALO·전화는 자동 수집이 안 됩니다.** 공식 API가 없고, 대화 DB를 직접 뜯는 건
  약관 문제가 있어 하지 않았습니다. 그런 건 대기열 엑셀에 직접 한 줄 추가하시면 됩니다.
- 메일을 **읽기만** 합니다. 보내거나 지우거나 옮기지 않습니다.
  주간보고도 **초안만 띄웁니다** — 보내기는 사람이 누릅니다.

## 데이터

전부 이 PC 안에만 있습니다.

```
data/snapshots/   대기열 원본 (무엇이 지워졌는지 알기 위해)
data/daily.jsonl  확정된 업무 기록
data/stats.json   학습 통계
queue/            매일 만들어지는 대기열 엑셀
```

**`data/`와 `queue/`는 git에 올라가지 않습니다.** 회사 메일 제목이 들어 있기 때문입니다.

## 개발

```bash
python3 -m unittest discover -s tests -t .
```

40개 테스트가 **Outlook 없이** 돕니다. `daily_log/outlook.py`만 Windows 전용이고,
나머지 로직(포함 규칙·학습·대기열·확정·주간보고)은 전부 가짜 데이터로 검증됩니다.

로직이 틀렸는지는 Windows 없이도 알 수 있고, `outlook.py`가 틀렸는지는 실제로 돌려봐야 압니다.
그래서 `demo`부터 해보시는 게 좋습니다.
