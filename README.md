# 개인 도구 — 업무·투자 기록 시스템

수익화 경로는 종료했고(근거는 [`DECISIONS.md`](./DECISIONS.md)), 지금은 **본인 업무와 투자를
효율화하는 도구**를 만든다.

## 지금 할 일

👉 **[`APPROVALS.md`](./APPROVALS.md)** — 다음에 뭘 하면 되는지가 적혀 있다.

## 왜 이 두 가지인가

두 문제의 뿌리가 같기 때문이다.

| 증상 | 실제 원인 |
|---|---|
| 손실이 계속 나는데 왜인지 모른다 | **매매 기록과 복기가 없다** |
| 업무가 정리되지 않는다 | **뭘 하고 있는지 목록이 없다** |

별개의 두 프로젝트가 아니라 **같은 사이클(기록 → 패턴 발견 → 개선)을 두 영역에 적용**하는
하나의 작업이다. 그래서 동시 진행이 자연스럽다.

**첫 단계는 자동화가 아니라 가시화다.** 뭘 하는지 모르면 뭘 고칠지도 모른다.

## 산출물

| 파일 | 하는 일 |
|---|---|
| `dist/매매복기.xlsx` | 손실의 원인을 숫자로 드러낸다 |
| `dist/반복업무_인벤토리.xlsx` | 시간이 어디로 새는지 보여주고 자동화 순위를 매긴다 |

두 파일 모두 **수식을 실제 계산시켜 검증**했다. `python3 -m engine.products.verify`

## 아키텍처: 엑셀은 UI, 파이썬은 자동화

| 역할 | 도구 | 이유 |
|---|---|---|
| 기록·조회 | **엑셀** | 입력이 압도적으로 편하고, 볼 때 별도 실행이 필요 없다 |
| 수집·변환·자동화 | **파이썬** | 증권사 CSV 파싱, 업무 반복 작업 자동화 |

**파이썬이 데이터를 넣어주고, 사람은 엑셀에서 본다.** 이 조합이 입력 부담을 가장 크게 줄인다.
지속 가능성이 정확도보다 중요하다 — 매주 1시간 걸리는 시스템은 3주 만에 죽는다.

## 매매 복기 시트가 보여주는 것

| # | 항목 | 왜 중요한가 |
|---|---|---|
| ① | **처분효과** — 이익 종목 평균 보유일 vs 손실 종목 평균 보유일 | 손실을 더 오래 들고 있으면 손절이 늦다는 뜻. 손실의 가장 흔한 원인 |
| ② | **규율** — 미리 정한 기준을 지킨 매매 vs 어긴 매매 | 소수 종목 집중 전략의 핵심 지표 |
| ③ | **비용** — 수수료·거래세 누적, "비용이 없었다면" | 매매가 잦으면 여기서 샌다 |
| ④ | **지수 대비** — 그냥 지수를 들고 있었다면 | 가장 냉정한 기준 |
| ⑤~⑦ | 월별·보유기간 분포·종목별 | 스타일과 편중 파악 |

각 진단에는 조건부 문구가 붙어 **무엇이 문제인지 문장으로** 알려준다.

## 이 도구가 하지 않는 것

- **종목 추천·매매 신호·목표가·수익률 전망** — 손실 중일 때 "만회해주는" 도구는 위험하다.
  기록과 복기만 한다.
- **회사 데이터를 저장소에 올리기** — 도구만 저장소에, 데이터는 로컬에.
- **세무·투자 자문** — 계산은 참고용이며 신고와 판단은 본인 몫이다.

**도구는 손실을 멈춰주지 못한다. 손실이 어디서 나는지 보여줄 뿐이다.**

## 명령어

```bash
pip install openpyxl PyYAML
python3 -m engine.products.build     # dist/ 에 두 시트 생성
python3 -m engine.products.verify    # 수식을 실제 계산시켜 검증 (formulas 필요, 수 분 소요)
```
